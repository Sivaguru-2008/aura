# AURA Scientific Benchmarking Protocol

This protocol defines the seven methodological rules governing all model comparisons in the AURA project. It is committed to version control to provide verifiable provenance and prevent post-hoc changes to evaluation metrics or comparison baselines.

## Protocol Rules

### P1. Per-Arm Calibration
Each backend must fit its own calibration parameters (e.g., temperature $T$ for scaling, Platt scaling parameters) on the calibration split before any downstream performance metrics are computed. Comparing a calibrated model to an uncalibrated baseline (or using a single global temperature fitted to one backend) is strictly prohibited.

### P2. Matched Capacity within an Ablation
Where an architectural factor (such as entanglement or circuit depth) is ablated, the compared arms must have identical trainable parameter counts and be trained by the same function on the same data with the same seed. Parameter count is a minimum requirement; where possible, effective capacity should be analyzed using measures like effective dimension.

### P3. Disjoint Splits at the Correct Unit
All dataset splits must be disjoint at the appropriate unit of clinical independence:
*   **Chest Radiography (Thorax):** Disjoint at the **patient** level (multiple films from the same patient must not span splits).
*   **Brain Segmentation (NeuroMind):** Disjoint at the **volume** level.
*   **Glioma Grading (Kernel Classifier):** Disjoint at the **subject** level (slices from the same subject must not cross splits).

Resampling (e.g., bootstrap) must be clustered at the same unit of independence.

### P4. Significance Before Ranking
No performance ordering or superiority claim may be asserted without an accompanying statistical significance test (e.g., McNemar's test for accuracy, Wilcoxon signed-rank for negative log-likelihood, DeLong's test for AUROC), confidence intervals, and a declared multiplicity adjustment policy (e.g., Holm-Bonferroni) within each test family.

### P5. Publication of Negative Outcomes
All comparison runs and evaluations must be reported in full, regardless of whether they support or contradict the initial hypothesis of quantum utility. Favorable sub-metrics (such as calibration) must not be reported in isolation if the proper scoring rule moves unfavorably.

### P6. Artifact-Derived Reporting
Every published figure, table, and statistical value in the manuscript must be read directly from the serialized JSON/NPZ artifacts generated by the evaluation pipeline. The build must include automated tests (e.g., `test_doc_numbers.py`) to verify that the documentation matches the artifacts.

### P7. Audit of Mechanisms, Not Only Metrics
Any claim regarding what a model is able to express or compute must be verified by a source-code level audit of the implementation (Rule P7). Metrics cannot falsify a capability that holds by construction, and capability claims must not be evaluated using simulated shortcuts.
